# Risk Register

Mitigations for the risks named in [PRD.md §15](PRD.md#15-risks). Each mitigation is a
design property of this system, not an aspiration; the linked mechanism is where it lives.

| # | Risk | Mitigation in this design |
|---|------|---------------------------|
| 1 | **Poor entity resolution** | Canonical `companies` table seeded from SEC's official ticker registry before any document ingestion. Extraction is deterministic with precision guards: tickers match only in cashtag/exchange contexts (`$NVDA`, `(NASDAQ: NVDA)`), never as bare words; names match on word boundaries with a minimum-length guard. Resolution version is recorded on every link, so an improved resolver reprocesses cleanly. Eval framework (Phase 8) measures resolution regressions. |
| 2 | **Weak retrieval quality** | Hybrid retrieval by design (Bible §16): lexical FTS + semantic pgvector fused with reciprocal rank fusion, plus metadata, entity, temporal, and graph signals — never vector search alone. A versioned golden question set with hit-rate/MRR tracking (`argus eval retrieval`) makes quality measurable per pipeline version. |
| 3 | **Hallucinated summaries** | Evidence-first boundary (ADR-0005): agents may only synthesize from evidence records that carry chunk-level citations; uncited evidence is rejected before it reaches the report drafter. Reports must contain contradicting-evidence and missing-information sections. Confidence is computed deterministically from evidence properties, never generated by the LLM. |
| 4 | **Incomplete provenance** | Provenance is schema-enforced, not convention: chunks reference documents, graph edges carry `source_document_id`, evidence rows reference chunks, and `investigation_events` records every prompt, retrieval strategy version, model version, and retrieved document ID. An investigation is replayable end to end. |
| 5 | **Connector instability** | Connectors implement a narrow protocol (`discover`/`fetch`) and are independently testable against recorded fixtures. The framework — not connectors — owns dedupe, retries with counts, and rate limiting. Failures land in `pipeline_runs` and dead-letter visibly; one broken connector cannot corrupt the pipeline because ingestion is idempotent and event-driven. |
| 6 | **Knowledge graph inconsistency** | Edges are only created by deterministic resolution against canonical IDs and always carry source-document provenance. Derived artifacts are disposable (Bible §14): the entire graph can be rebuilt from raw documents via `argus reprocess` if a resolver bug corrupts it. |
| 7 | **Data freshness issues** | Per-connector schedules (RSS 15m, SEC hourly, profiles daily) with last-run/next-run visible on the pipeline dashboard. Ingestion timestamps are first-class metadata; the knowledge-evolution consumer flags investigations when new documents touch their entities, so staleness is surfaced rather than silent. |
